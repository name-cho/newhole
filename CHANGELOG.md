# Changelog

All notable changes to this fork are documented here. The project started as a fork of
[loophole/cli](https://github.com/loophole/cli) and follows the same protocol, so the
Loophole gateway and API keep working.

## Unreleased

### Tunneling and reconnects

* Reconnect forever (or `NEWHOLE_MAX_RECONNECTS` times) with exponential backoff instead of
  giving up after five attempts, so network outages, laptop suspends and gateway restarts
  no longer kill the tunnel.
* Keepalives are sent every 30 seconds without waiting for a reply, so a dead connection is
  detected and replaced instead of hanging on `Initializing secure tunnel... Success!`.
* The `tcpip-forward` request has its own timeout, a denied port is retried with backoff and
  the reason (`another copy of the tunnel may still hold it`) is shown.
* `--hostkey-policy known_hosts` validates the gateway key against `~/.ssh/known_hosts`.
* Legacy RSA keys are converted to PKCS#8 in place, so current OpenSSH installs can use the
  key generated by older releases.

### HTTP proxy

* The `Host` header sent to the local service is now the public hostname
  (`<hostname>.<domain>`) instead of `127.0.0.1:<port>`; `--override-host` and
  `--preserve-host` give explicit control.
* Real client IP forwarding in `X-Forwarded-For`/`X-Real-IP`, with spoofed inbound values
  removed.
* Query strings and headers larger than 8 KiB work (`--max-header-bytes`, default 1 MiB),
  request bodies can be capped (`--max-body-bytes`), CORS preflights can be answered
  (`--cors`) and an optional per-IP rate limiter is available (`--rate-limit`).
* Unix socket upstreams: `newhole http unix:/run/app.sock`.
* Directory listings are off by default and `--directory-listing` enables them.
* `--compress` negotiates gzip with the local service, so compressed payloads travel over
  the tunnel instead of raw bytes (compression inside SSH streams hurts more than it helps,
  which is why this is opt-in).
* Client disconnects (`context canceled`, `broken pipe`) are logged at debug level instead of
  being printed as errors.
* TLS noise (`first record does not look like a TLS handshake`, `bad record MAC`, old TLS
  versions, missing certificates) is classified and logged at debug level with an
  explanation.

### Authentication and API

* Device code, refresh token and token storage reworked: tokens are written atomically with
  `0600`, corrupted files produce an actionable message and the refresh token is actually
  refreshed on a 401.
* The last time the session was used is stored and shown by `newhole account whoami`, which
  warns when the refresh token has probably expired.
* API errors are decoded from JSON, HTML error pages, captive portals and timeouts, each
  with a hint; 5xx responses during registration are retried with backoff.
* `NEWHOLE_TOKEN` and `--token` authenticate without any local storage.

### New commands

* `newhole` without arguments starts an interactive wizard (login, what to expose, which
  hostname) and `newhole --last` repeats the previous tunnel.
* `newhole account hostnames` lists the hostnames used on this machine (`--json`,
  `--forget <name>`), `newhole account unregister <name>` releases one.
* `newhole --daemon` detaches the tunnel, `newhole status` and `newhole stop` manage it.
* `newhole update [--check]` downloads the newest release and replaces the binary.
* `newhole feedback` opens the issue tracker.
* `newhole path`, `newhole webdav`, `newhole http` validate their arguments before any
  network or UI work starts.

### Desktop application

* Rewritten UI server: same-origin websocket check, tunnel registry with locking, tunnels are
  stopped when the window closes, failing tunnels no longer leak slots and errors are
  reported instead of killing the process.
* Chromium 70+ works (`--remote-allow-origins` is passed to Chrome).
* Hostname history and "reuse the last tunnel" are available in the UI.
* Tunnels survive a window reload: the active tunnel configurations are stored in
  `active-tunnels.json` and restored on the next start.

### Packaging and project

* Renamed to `newhole` everywhere: binary, module, storage directory (`~/.newhole`, the old
  `~/.loophole` is migrated), messages, docs and the desktop bundle.
* GoReleaser publishes plain `newhole_<version>_<os>_<arch>` archives (which `newhole update`
  expects), ARMv5 builds, deb/rpm/apk packages, a Homebrew formula, checksums signed with
  cosign and SBOMs.
* GitHub Actions run tests and vet with both build tags on Linux, macOS and Windows.

### Known limitations

* The Loophole API has no endpoint for deleting a site, so `newhole account unregister` only
  drops the local reservation; the gateway frees an unused hostname 30 days after its last
  tunnel.
* Binary signing (Apple notarisation, Authenticode) needs the maintainer's certificates; the
  release workflow produces checksums and cosign signatures instead.
* UDP is not part of the Loophole protocol the client speaks, so only TCP tunnels are
  available.
